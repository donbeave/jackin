**Status**: Partially implemented

**Current state**: jackin❯ desktop ships one native status item per auto-detected provider, a focused usage popover, the Capsule-parity Usage window, host-global snapshot coordination, and secret-free release validation. This implementation is deliberately accepted as a functional baseline, not as visual parity: its native composition and feel remain materially short of the canonical HTML design. Visual alignment continues in a follow-up pull request. Public notarized distribution and production acceptance also remain unfinished, so this item cannot retire yet.

## Shipped baseline

- Rust owns provider probes, account selection, shared snapshots, quota semantics, severity, and every displayed usage string. Swift is a native display shell over UniFFI.
- One status item per detected provider shows the Rust-selected glance window; the popover provides Overview/provider tabs and Refresh; the Usage window renders the shared Capsule detail presentation.
- Stale-last-good, refreshing, unavailable, unsupported, authentication, and provider-error states remain distinct. Failed refreshes do not erase last-good data.
- macOS 26 Liquid Glass gates stay centralized in the native fallback layer; macOS 14–15 and Reduce Transparency use system materials.
- The release workflow can build and validate the arm64 static app, generate the future cask, reconcile partial release states, and run install-proof automation without Apple credentials.

Operator behavior lives in [macOS agent-usage menu bar](/guides/macos-usage-menu-bar/). Architecture and release boundaries live in [ADR-011](/reference/adrs/adr-011-native-macos-usage-menu-bar/) and <RepoFile path="native/README.md" />.

## Remaining work

### Production activation and proof

As of 2026-08-09, the `release-macos` environment has none of the five required Apple secrets, the repository has neither required signing variable, no jackin❯ desktop release asset exists, and the Homebrew tap has no `jackin-desktop` cask. Secret-free validation passing does not satisfy these production requirements.

1. Provision the Developer ID Application certificate, App Store Connect notarization key, team id, and pinned certificate fingerprint through the documented operator path. Credentials must remain confined to the GitHub-hosted macOS release environment and be deleted before supply-chain tooling runs.
2. Cut the first non-development release from `main`; run publish mode; sign, notarize, staple, and Gatekeeper-validate `JackinDesktop.app`; then publish the immutable ZIP, SHA-256 sidecar, Sigstore bundle, SBOM, and GitHub attestation. Verify the downloaded artifact with `cargo xtask release-verify`.
3. Advance the stable formula and `jackin-desktop` cask in one independently checked tap PR. The first cask requires operator review and merge; it must not auto-merge from the credentials-bearing workflow.
4. On Apple Silicon macOS 14+, install from the public cask, launch the installed app, exercise the status item/popover/Usage window, uninstall cleanly, and prove a completed-version release rerun makes no writes. Retain partial/conflict fail-closed behavior.
5. Reconcile durable operator, architecture, and release-verification docs with observed production behavior. Only then retire this roadmap page; canonical docs and Git history retain the shipped record.

### Native interaction and visual acceptance

The durable design oracle is `plans/previews/desktop-ui/index.html`, `popover.html`, and their adjacent `SPECIFICATION.md`. Historical implementation plans, progress screenshots, and visual-diff journals were removed because they described a process, not the desired product. Structural tests, full-Xcode tests, pure Swift harnesses, build verification, and ephemeral launch smokes do not prove visual parity.

- Continue direct HTML-to-running-app alignment in the next pull request. Treat the current native UI as a baseline to improve, never as the visual source of truth.

- Run real Apple Silicon acceptance on macOS 14 fallback materials and macOS 26 Liquid Glass, covering light/dark appearance, Increase Contrast, Reduce Transparency, mouse, keyboard-only navigation, VoiceOver, and screen-sharing privacy transitions.
- Exercise no providers, one provider, all detected providers, dual and many-window quotas, multi-account selection, very long labels, refreshing, fresh, stale-last-good, depleted-with-reset, needs-login, unsupported, and provider-error states at minimum and large window sizes. Include remembered sizing, repeated open/close, and simultaneous popover/Usage-window behavior.
- Compare jackin❯ desktop, Capsule, and `jackin usage` from the same serialized snapshots; every quota/account string and ordering decision must agree. Retain redacted evidence.
- Compare the running native status items, Overview/provider popover tabs, Usage window, and state families directly with the HTML oracle. Temporary local captures may assist review, but progress screenshots and visual-diff artifacts do not belong in the repository. Current source-confinement and presentation harnesses prove ownership and structure, not pixel output.

### Capture-gated provider work

- Capture authenticated Amp Megawatt, Gigawatt, and linked-subscription `displayText` or `userDisplayBalanceInfo` responses, then add paid-plan/monthly parsing without regressing Amp Free Daily. This remains blocked on a real operator-owned capture; guessed wire shapes are not acceptable.

### Deferred product candidates

These came from the superseded screen roadmap and remain ideas, not part of the shipped v1 contract:

- an All Accounts Usage view showing deterministic account winners across live, durable, and shared sources;
- a Status & Sources Usage view for freshness, credential origin, last success, and last-good/error state;
- Rust-owned provider quick links, incident metadata, reset-credit expiry details, collapsible secondary quota metrics, and segmented capacity markers;
- a future configuration UI. The old single-status-item display modes and Settings-centric provider toggles were superseded by auto-detected per-provider items and must not be revived without a new design decision.

## Superseded plan work

The old native program's main-actor bridge, shared-snapshot authority, Rust-owned presentation, CI, compact-glance, state, terminology, and Usage-detail defects were resolved by the shipped jackin❯ desktop program. Its single-item/Settings screen contract was deliberately replaced. Only production activation/proof, live visual acceptance, capture-gated Amp work, and the explicitly deferred candidates above remain.
