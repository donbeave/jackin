- **010 — Dialog and form layer**: adopt `confirm_prompt`/`alert_dialog`/`error_state`/`loading_overlay` (default-focus-No verified), `file_picker`/`file_tree`/`path_input` (domain rules re-hosted), `select`/`combobox`, `form`/`field_row`/`key_value_table`/`password_input`, render-only `diff`, and `key_value_table` + `link`.
- **011 — Layout, chrome, runtime**: adopt `panel_stack`, `kbd` + `hint_bar` (hint priorities and RULES.md labels re-verified), `SpinnerState`, `keymap_bridge`/`UiIntent` (Visibility metadata survives), `Presenter`/`FrameClock`/`ReadySubscription` (run loop stays surface-owned), and `resizable_panel_group` with seam-drag parity.
- **012 — Recipes, wizard, keyboard_help**: copy-adapt the workspaces/settings/auth screen recipes, re-host the create-prelude wizard on `form_wizard`, and add the sanctioned `keyboard_help` overlay (`?` everywhere, keymap_bridge-sourced, footer-hint discovery, PNG-baselined).

## Repo law binding every plan

- Never commit to `main`. All ten plans execute on `roadmap/termrock-migration` (operator directive 2026-08-20: one branch only, never create new branches) so the working tree carries this plans package (check before the first commit: `test -f plans/termrock-migration/goal-check.sh`). `git branch --show-current` must print `roadmap/termrock-migration` before any code commit. One PR for the package, opened from `roadmap/termrock-migration`; open it as draft after plan 005's first push with `gh pr create --draft --body-file` per the PR template at `.github/PULL_REQUEST_TEMPLATE.md`.
- **Artifacts never merge.** Planning artifacts (`plans/`, `roadmap/`, `research/`) ride the execution branch during work (status flips commit with the work), and plan 014 strips them from the merge diff with a dedicated `git rm -rq plans/ roadmap/ research/` commit before merge-readiness — the merged PR carries code only, exactly like PR #897. A PR carrying artifacts into main's history is closed, not merged (standing operator rule).
- Every commit: Conventional Commits subject, DCO sign-off (`git commit -s`), push immediately after every commit. Never force-push without explicit operator approval.
- Brand word in prose/docs/PR text is `jackin❯` (plain `jackin` only for identifiers/paths/commands).
- Pre-release: breaking changes allowed, no migration shims; `deny.toml` and `Cargo.lock` changes ride the same commit as the dependency change they serve.
- UI/UX parity invariant (D16): every console screen keeps its current look and interaction behavior. **Any console text-snapshot diff during plans 006–013 is a parity break: STOP for operator review — never re-bless.** PNG baseline re-blesses happen only in plan 005 (initial bless) and plan 014 (deliberate, reviewed).
- Same-PR docs law: TUI reference pages under `docs/content/reference/tui/` that describe adopted machinery are updated in plan 014 (intermediate plans note drift; the PR merges with docs aligned).
- Merge is the operator's; plans never merge, never mark ready without the operator.
- **TermRock is jackin❯-controlled and changeable (item decision 2026-08-19).** TermRock began as code exported from jackin❯ to become a reusable TUI component library, and jackin❯ is today its only consumer — so when a TermRock API does not fit jackin❯, the preferred fix is extending or refactoring TermRock itself (breaking changes acceptable) to serve both jackin❯ and the library's general-purpose role, never a jackin❯-side workaround or shim (N2). Executor route when this arises: the TermRock repository is outside this package's scope — do NOT edit the checkout; mark the row `BLOCKED (termrock API misfit — recommend upstream change: <one line>)` with the concrete API gap and the shape of the upstream change you would make, and stop. The operator lands the TermRock change, re-pins the rev, and either resumes or re-plans. An API-misfit BLOCKED is a correct outcome, not a failure.
