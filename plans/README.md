## Findings considered and rejected

- **Keep fuzzy alias matching and patch Z.AI/MiniMax specially**: rejected. Routing
  identity and provider ownership are different types; an exception preserves the bug
  class for future routed providers.
- **Let old snapshots remain active accounts indefinitely**: rejected. Current
  config-derived sources define active membership. Durable history may enrich a
  discovered account but cannot create one; this avoids inventing an account-removal
  UI or showing ambiguous parallel logins.
- **Treat local credential presence as an account**: rejected. No stable authenticated
  identity exists. It is provider/source state, not a subscription account.
- **Show OpenCode/GitHub because config discovery sees them**: rejected. The frozen
  Desktop quota contract explicitly excludes OpenCode, and GitHub auth has no quota
  surface here.
- **Continue shared files with stronger `flock` use**: rejected. Docker Desktop does
  not provide the required documented cross-host/container lock guarantee, and a
  shared directory cannot enforce per-Capsule account visibility.
- **Fall back to unlocked probing when broker/storage is unavailable**: rejected.
  This directly violates the one-query invariant. Failure must be typed and fail closed.
- **Expose the global broker socket read-only to Capsules**: rejected. Read-only still
  reveals global account metadata and cannot express per-account request authority.
