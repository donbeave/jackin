## Open unknowns

- **Semantics, not compilation**: the fixpoint proves type-level compatibility only. The `FocusRing`→`InteractionScene`, `ModalStack`→`OverlayStack`, and `DiffViewState` scroll-ownership migrations are redesigns whose behavior (focus restoration, Esc cascade, outside-click dismissal, diff scrolling) was not exercised — the clone shims vendored old code or dropped writes. Visual parity (docs 0327-0331, PNG baseline workflow `mise run png-baselines` in TermRock) was not assessed.
- The correct palette endpoint per site (plain `DesignSystem::default()` vs `RolePalette::tailrocks_phosphor()`+`from_palette` vs jackin brand palette via `with_role`) is a design decision the sweep did not make; the compile inventory is endpoint-agnostic.
- Lint-gate fallout under the workspace's deny-warnings baseline (e.g. `unused_qualifications` after import moves) will add noise not counted here.
- `cargo xtask ci` lanes (feature powerset, `--all-features`, Docker e2e, `jackin-capsule` smoke) were not run against the patched tree; only default-feature `cargo check`/`--tests` for the six termrock consumers.
- The `jackin` crate's Theme-class count (7 sites, one file) is static (`rg`), not compiler-enumerated, because the crate was dependency-blocked until after the sweep; its two struct-literal errors were compiler-measured post-sweep and the crate then compiled clean, so the residual risk is nil-to-low.
- ~~No migration doc names the `ListState::for_count` const-ness change~~ — resolved second pass: doc 0083 covers it via `ListState::new` ("no longer const"); the change is intentional and documented, just not under the `for_count` symbol.
