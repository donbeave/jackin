## Findings

### Pipeline anatomy

- **Crate**: `crates/termrock-raster`, package `termrock-raster`, workspace member (root `Cargo.toml:8` members list), `publish = false` (`crates/termrock-raster/Cargo.toml:12`), description "Deterministic ratatui Buffer + RolePalette to PNG rasterizer for TermRock baselines" (`crates/termrock-raster/Cargo.toml:11`). Dependencies: `termrock` (path+version), `ratatui` (no default features), `swash`, `tiny-skia`, `unicode-width` (`Cargo.toml:15-19`). Confidence: HIGH.
- **Public API** (`src/lib.rs:14-24`): `compare_png_pixels`, `PixelDiff` (re-export from `compare.rs`); `render_pixmap`, `render_png`, `RenderError` (from `render.rs`); public constants `CELL_WIDTH_PX = 9`, `CELL_HEIGHT_PX = 18`, `FONT_SIZE_PX = 14.0`, `BASELINE_PX = 14` — documented as "matches the frame/preview seam". Confidence: HIGH.
- **Buffer → pixmap** (`src/render.rs:90-169`, `render_pixmap(buffer: &ratatui::buffer::Buffer, palette: &termrock::style::RolePalette)`):
  1. Pixmap dimensions = buffer area × 9×18 px cells (`render.rs:94-101`); whole canvas pre-filled with the palette's `Role::Canvas` background (`render.rs:102-106`).
  2. Per cell: fg/bg resolved by `color_to_rgb` (`src/color.rs:47-74` — named ratatui colors mapped to the phosphor-flavoured RGB table, `Color::Indexed` via an xterm-256 table at `color.rs:8-43`; both carry the comment "Duplicated by decision in plan 001; keep in lockstep" with `crates/termrock-lookbook/src/palette256.rs` / `frame.rs:201-228`). `REVERSED` swaps fg/bg (`render.rs:115-117`); `DIM` multiplies fg channels by 0.6 (`render.rs:118-120`).
  3. Cell span from `unicode_width::UnicodeWidthStr::width(symbol)` clamped to 1..=2 (wide graphemes paint two cells; the shadow cell is skipped by advancing `column += span`, `render.rs:122-127,165`).
  4. Glyphs: face selected by modifier (`src/fonts.rs:12-21`), swash scaler built at size 14 with `.hint(true)` (`render.rs:132-136`), then **per-char** `font.charmap().map(character)` and `Render::new(&[Source::Outline]).format(Format::Alpha)` — outline-only source, 8-bit alpha mask, **no shaping engine** (`render.rs:137-142`). Compositing is hand-written integer alpha blending over the pixmap (`render.rs:52-87`); backgrounds are hand-written rect fills (`render.rs:36-50`). tiny-skia is used as pixmap storage and PNG codec, not as a path rasterizer.
  5. `UNDERLINED` = 2 px bar at cell y-offset 15; `CROSSED_OUT` = 2 px bar at y-offset 8 (`render.rs:159-164`).
  6. `render_png` = `render_pixmap(..)?.encode_png()` via tiny-skia (`render.rs:172-176`). Confidence: HIGH.
- **Palette**: baselines render with `RolePalette::default()`, which is `RolePalette::tailrocks_phosphor()` (`crates/termrock/src/style/mod.rs:839-843`; used at `crates/termrock-lookbook/src/png.rs:59`). Confidence: HIGH.
- **Story glue (TermRock-internal, not part of the raster crate)**: `crates/termrock-lookbook/src/png.rs` — `JACKIN_SUBSET_COMPONENTS` (17 component names, `png.rs:19-37`), `subset_stories()` filter+sort (`png.rs:41-48`), `story_png_filename` (`id.replace('/', "-") + ".png"`, `png.rs:52-54`), `render_story_png` (paint story buffer, then `termrock_raster::render_png`, `png.rs:58-62`), `write_story_pngs` (`png.rs:65-76`). The raster dep is optional in the lookbook, enabled by its default `native` feature (`crates/termrock-lookbook/Cargo.toml:20-25`). Confidence: HIGH.

### Font and determinism

- **Font**: JetBrains Mono, three static faces vendored at `crates/termrock-raster/assets/fonts/` (Regular 273,900 B, Bold 277,828 B, Italic 276,840 B; method: `stat -f %z`), embedded into the binary with `include_bytes!` (`src/fonts.rs:7-9`). No BoldItalic face: Bold wins when both modifiers are set (`fonts.rs:11-19`). Confidence: HIGH.
- **Version**: v2.304. The vendored `JetBrainsMono-Regular.ttf` sha256 (`a0bf60ef0f83c5ed4d7a75d45838548b1f6873372dfac88f71804491898d138f`, measured locally with `shasum -a 256`) equals the hash TermRock's research recorded for `JetBrainsMono-Regular.ttf` inside the official release artifact `https://github.com/JetBrains/JetBrainsMono/releases/download/v2.304/JetBrainsMono-2.304.zip` (`research/tui-png-baselines/06-rasterizer-facts-and-archtest.md:42`). All three hashes are additionally pinned by a unit test (`src/fonts.rs:30-52`) and match the on-disk files (measured). Confidence: HIGH for hash identity with the recorded release hash; the release-zip provenance itself is TermRock's cited primary download URL (lead verified by hash equality, not re-downloaded here).
- **License**: OFL-1.1. `REUSE.toml:12-16` annotates `crates/termrock-raster/assets/fonts/**` as `SPDX-License-Identifier: OFL-1.1`, copyright "2020 The JetBrains Mono Project Authors (https://github.com/JetBrains/JetBrainsMono)"; the license text is committed at `LICENSES/OFL-1.1.txt`. Confidence: HIGH.
- **Determinism model**: no OS text stack is involved at any point — vendored font bytes, swash (pure-Rust scaler, exact-pinned `swash = "=0.2.10"`) and tiny-skia (exact-pinned `tiny-skia = "=0.12.0"`) in the workspace `Cargo.toml:38-39`. Hinting **is** enabled (`.hint(true)`, `render.rs:135`) and anti-aliasing exists (8-bit alpha masks) — but both are computed by swash itself, so they are platform-independent by construction rather than by disabling them; there is no FreeType, CoreText, fontconfig, GPU, or environment input. The design rationale and the "escape the OS text stack" argument are documented in `research/tui-png-baselines/README.md:29-35` (headline 3). Confidence: HIGH for the code facts; the cross-platform claim decomposes below.
- **Measured determinism evidence**:
  - Cross-arch: swash 0.2.10 + tiny-skia 0.12.0 + JBM 2.304 produced identical raw-RGBA and PNG sha256 on aarch64 native vs x86_64-under-Rosetta, double runs identical (`research/tui-png-baselines/README.md:70-79`, method in chapter 06). Both binaries ran on one OS, so this does **not** cover macOS↔Linux (`06-rasterizer-facts-and-archtest.md:87,107`). Confidence: HIGH that this is what was measured (primary doc read).
  - macOS↔Linux same-toolchain identity is carried as **assumption A3** in a plan ledger (`README.md:79`) that is not committed anywhere in the repo (searched `research/`, `roadmap/`, `artifacts/` — empty/absent). The shipped test's failure message encodes the contingency: "If this fails only on Linux CI against a macOS-blessed baseline with no intended paint change, ledger assumption A3 is falsified: use its pinned-Linux or CI-produced bless fallback instead of re-blessing on macOS" (`crates/termrock-lookbook/tests/png_baselines.rs:69`). Confidence: HIGH for the text; the ledger itself is an open unknown.
  - This-host reproduction (experiment): `cargo test -p termrock-lookbook --all-features --test png_baselines --locked` on macOS 26.5.2 / arm64 / rustc 1.97.1 passed — all 107 committed baselines reproduced pixel-exactly at zero tolerance (compile 20.4 s, test 19.2 s; target dir in scratchpad; repo untouched). Confidence: HIGH (measured).
  - In-process render-twice identity is asserted for every story on every run, with an explicit "PIPELINE BUG … do NOT resolve it by blessing" message (`png_baselines.rs:41-46`). Confidence: HIGH.
- **Policy on platform drift**: migration 0331 — "A platform-only mismatch with no intended paint change is a raster pipeline defect and must not be blessed" (`migrations/0331-v0.14.0-jackin-parity-handoff.md`, PNG regression workflow section). Confidence: HIGH.

### Workflow and baselines

- **`mise run png-baselines`** = `cargo nextest run -p termrock-lookbook --all-features --test png_baselines --locked` (`mise.toml:82-84`). **`mise run bless-pngs`** = `TERMROCK_BLESS_PNGS=1 cargo nextest run -p termrock-lookbook --all-features --test png_baselines --no-capture` (`mise.toml:78-80`). Both drive the single test `subset_stories_match_their_png_baselines` in `crates/termrock-lookbook/tests/png_baselines.rs:24-72`; bless mode is just the env var making the test write `fs::write(path, first_render)` instead of comparing (`png_baselines.rs:26-29,48-52`). Confidence: HIGH.
- **Baselines**: `crates/termrock-lookbook/baselines/png/` — exactly 107 committed PNGs (method: `git ls-files … | wc -l` = 107), all introduced in `e1d61f4d` (`git log -- crates/termrock-lookbook/baselines/png` shows only that commit). Filenames are story ids with `/`→`-` (e.g. `panel-focused.png`). A rot guard asserts the subset filter still yields ≥ 87 stories (`png_baselines.rs:31-36`). Confidence: HIGH.
- **Zero-tolerance compare**: `compare_png_pixels` (`crates/termrock-raster/src/compare.rs:49-84`) decodes both PNGs with `tiny_skia::Pixmap::decode_png`, fails on decode error or dimension mismatch, then compares RGBA in `chunks_exact(4)` and reports the **first differing pixel** with coordinates and both RGBA values (`PixelDiff::FirstDifference`, `compare.rs:23-33`). Decoded pixels, never encoded bytes — stated in the crate docs (`lib.rs:7`) and in migration 0331 ("decoded pixels at zero tolerance, not encoded PNG bytes"); rationale (PNG encoder byte churn across versions) at `research/tui-png-baselines/README.md:36-40`. Confidence: HIGH.
- **Gate placement in TermRock**: the test also runs under plain workspace nextest — `mise run check`/`test` execute `cargo nextest run --workspace --all-features --locked` (`mise.toml:23-42`), and `mise run gate` additionally invokes `mise run png-baselines` explicitly (`mise.toml:52`). PR CI is a generated velnor-actions consumer: `.github/workflows/ci.yml:106,128,150` delegate to owner-local SHA-pinned `velnor-actions/.github/workflows/ci-code.yml`; per TermRock's own research, that lane runs exactly the repo's mise tasks and all PR runners are Linux (`ubuntu-26.04` GitHub lane / Velnor self-hosted; no macOS lane) (`research/tui-png-baselines/README.md:64-72`, headline 8). The velnor-actions internals are external and were not read. Confidence: HIGH for mise.toml/ci.yml; MED for exact runner behavior (external pinned repo, doc-sourced).
- **Bless discipline**: after an intended paint change, inspect the rendered difference, run `mise run bless-pngs`, and "Commit every changed baseline in the same pull request" (`migrations/0331`, PNG regression workflow). Confidence: HIGH.

### Consumer adoption contract

- **What 0331 actually promises**: `migrations/0331-v0.14.0-jackin-parity-handoff.md` describes (a) the consumer API migration (imports move to current modules, `RolePalette::tailrocks_phosphor()` replaces the old root theme, `TerminalCellSource`/`TerminalCellGrid` and `ReadySubscription` become public); (b) the visual contract (Tabs/ChoiceDialog decisions, migrations 0327-0330); (c) the PNG regression workflow quoted above. It frames the PNG baselines as **TermRock's own** regression net over "the Jackin-used widget subset". It does **not** instruct the consumer to depend on `termrock-raster`, and it explicitly scopes out the historical side harness ("an audit tool, not a runtime dependency or consumer migration requirement"). Product compositions (BrandHeader, digital rain, launch animation) stay consumer-owned. A jackin❯-side PNG-baseline harness over jackin❯'s own screens is therefore **not specified by 0331** — it would be new consumer-side work reusing the public raster API. Confidence: HIGH (doc read in full).
- **Public API sufficiency from outside the workspace**: `render_png(&Buffer, &RolePalette)` and `compare_png_pixels(&[u8], &[u8])` take only ratatui and termrock types (`render.rs:90-93,172`; `compare.rs:49`) — no lookbook types required; the story/subset/filename machinery is lookbook-internal convenience. `termrock-raster` declares no cargo features of its own (`crates/termrock-raster/Cargo.toml` has no `[features]` table). The fonts ship inside the crate via `include_bytes!`, so a consumer needs no font files of its own. Confidence: HIGH.
- **Availability**: TermRock "is not published to crates.io" (`RELEASING.md:3-4`); `termrock-raster` and `termrock-lookbook` are additionally `publish = false` (`crates/termrock-raster/Cargo.toml:12`, `crates/termrock-lookbook/Cargo.toml:12`). External consumption is therefore git-dependency only. jackin❯ already consumes termrock exactly that way: `termrock = { version = "=0.11.0", git = "https://github.com/tailrocks/termrock.git", rev = "5ff94ee117fd4a1b72fdd0d1b1847815055a93ac", … }` (jackin `Cargo.toml:118`) — that rev is precisely the pre-parity revision 0331 names as the migration base — and jackin's `deny.toml:204` already allowlists `https://github.com/tailrocks/termrock.git` under `[sources].allow-git`. The `publish` manifest field gates registry publishing, not git-dependency resolution (Cargo Book, `https://doc.rust-lang.org/cargo/reference/manifest.html#the-publish-field`) — Confidence: HIGH for all file facts; MED for the publish-field behavior (stable primary-doc URL cited from knowledge, not re-fetched; trivially verified by a build).
- **Version-coherence constraint**: `termrock-raster` depends on `termrock` by path+version inside the TermRock workspace (`crates/termrock-raster/Cargo.toml:15`). A consumer adding it as a git dep must pin the **same repo rev** for both `termrock` and `termrock-raster` or cargo resolves two termrock copies with incompatible types. Confidence: HIGH (manifest read; standard cargo resolution).
- **License/policy deltas a consumer inherits**: the raster stack pulls tiny-skia (BSD-3-Clause) and arrayref (BSD-2-Clause) — TermRock had to widen its cargo-deny allowlist to include both (`deny.toml` in termrock: `allow = [… "BSD-3-Clause", "BSD-2-Clause"]`; background at `research/tui-png-baselines/README.md:81-88`, headline 10). jackin❯'s `deny.toml:16-19` allows only Apache-2.0 + MIT globally with per-crate `exceptions`; neither `swash`, `tiny-skia`, nor `arrayref` appears in jackin's `Cargo.lock` or exceptions today (grep: zero hits), so adoption adds new license exceptions. Committed baseline PNGs in the jackin repo would also need REUSE annotations (jackin runs a REUSE lane: `.github/workflows/reuse-compliance.yml`; root `REUSE.toml` exists); the OFL font files themselves stay inside the cargo git checkout and never enter jackin's tree. Confidence: HIGH for file facts; the REUSE-for-PNGs point is an inference from the existing lane (MED).
- **Workspace version note**: the TermRock workspace still stamps `version = "0.11.0"` (root `Cargo.toml:13`) while migrations 0300-0331 target `v0.14.0` and git tags stop at `v0.9.0` — see Dead ends and contradictions. Any dependency pin should use the git rev, not a version. Confidence: HIGH (files read).

- **TermRock consumers in-tree**: `termrock = { workspace = true }` in `crates/jackin-capsule`, `jackin-console`, `jackin-launch`, `jackin-oppicker`, `jackin-tui`, `jackin` (each crate's `Cargo.toml`; workspace pin at root `Cargo.toml:118`). Confidence: HIGH.
- **Existing snapshot tests**: insta, exact-pinned `insta = "=1.48.0"` (root `Cargo.toml:69`), `filters` feature in the two consuming crates (`crates/jackin-capsule/Cargo.toml:86`, `crates/jackin-console/Cargo.toml:32`). 18 committed `.snap` files in three directories: `crates/jackin-console/src/tui/view/snapshots/`, `crates/jackin-capsule/src/tui/components/dialog/snapshots/`, `crates/jackin-capsule/src/tui/components/branch_context_bar/snapshots/` (method: `find crates -name '*.snap' | wc -l`). Confidence: HIGH.
- **Snapshot governance**: changed `.snap` files are enumerated in CI against the PR merge-base with `origin/main`; `*.pending-snap` fails CI; hand-editing is rejected in review (`TESTING.md:181`). The enumerating implementation is not in-repo (searched workflows and xtask) — it lives in the external SHA-pinned velnor-actions repos. - **Runner/lanes**: `cargo xtask ci` partitions include a `snapshots` partition = `cargo nextest run -p jackin-capsule -p jackin-console --locked` (`crates/jackin-xtask/src/ci.rs:12-19,258-271`). nextest profiles in `.config/nextest.toml`: `default` (excludes Docker e2e binaries, line 5), `docker-e2e` (lines 8-16), `ci` (retries 2, flaky surfaced, junit; lines 21-27), `soak` (line 30). CI entry: generated velnor consumer `.github/workflows/ci.yml` delegating per-owner to SHA-pinned `velnor-actions/.github/workflows/ci-native.yml` (`ci.yml:106,128,150`); the in-repo reusable `.github/workflows/rust-nextest.yml` (a `workflow_call` workflow with no in-repo caller — invoked from velnor-actions) runs per-package `cargo nextest run … --profile ci` on a runner matrix injected via `runner-configs-json` (`rust-nextest.yml:9-16,98-100,267-274`). So render tests today run wherever the injected runner lanes say — the lane configs are not readable in this repo. Confidence: HIGH for in-repo files; the runner OS mix is an open unknown in-repo.
- **Other render-verification seam**: the capsule render-conformance harness replays reviewed PTY byte streams and asserts frame reproduction on a virtual client terminal — `crates/jackin-capsule/src/daemon/tests.rs`, fixtures under `crates/jackin-capsule/tests/fixtures/pty/`, capture via `JACKIN_PTY_FIXTURE_CAPTURE` + `cargo xtask pty-fixture` (`TESTING.md:192-199`). - **No PNG/raster machinery exists in jackin today**: no `swash`/`tiny-skia` in `Cargo.lock`, no image snapshot crates; `insta` is the only snapshot dependency (greps above). Confidence: HIGH.

### Costs

- **Baseline artifact size (measured at termrock HEAD)**: 107 PNGs, **708,135 bytes total** (~692 KiB; mean ≈ 6.6 KiB/file). Method: `find crates/termrock-lookbook/baselines/png -name '*.png' -exec stat -f %z {} +` summed with awk; `du -sk` reports 884 KiB on-disk (block rounding); file count via `git ls-files | wc -l`. Confidence: HIGH.
- **Font payload**: 828,568 bytes across the three TTFs (stat, above) — carried inside the `termrock-raster` crate source (cargo git checkout + compiled binary), not in a consumer's git history. Confidence: HIGH.
- **Runtime**: one full 107-story verify pass (each story rendered twice + compared + baseline compared) took 19.2 s test time after a 20.4 s incremental compile on this arm64 host (measured, cargo output). Confidence: HIGH (single sample, this host).
- **Git-history growth per re-bless (consideration, not verdict)**: PNGs are already deflate-compressed, so pack-time delta/zlib recovers little; each bless that rewrites the full set adds roughly one set of new blob bytes (~0.7 MB at TermRock's current set) to permanent history. TermRock's own research quantifies: ten full-set rewrites ≈ 5–150 MB worst case against its 118.17 MiB pack (`research/tui-png-baselines/04-determinism-ci-storage.md:65`, method `git count-objects -vH`; the "compressed data doesn't delta" premise is flagged MED there). For the jackin repo the multiplier is jackin❯'s own screen count × bless frequency — unmeasurable until a screen set is chosen. GitHub renders rich PR image diffs for plain-git PNGs but only pointer files for LFS objects (`04-determinism-ci-storage.md:66-76`, GitHub docs URLs cited there) — the reason TermRock chose plain git (`README.md:41-46`, headline 5). Confidence: HIGH for the sourced numbers; the jackin projection is arithmetic, not a finding.

## Dead ends and contradictions

- **Subset count drift**: `png_baselines.rs:34` says "the 16 subset components" in its assertion message, but `JACKIN_SUBSET_COMPONENTS` contains **17** entries (`png.rs:19-37`; counted). Stale message, not a functional bug — the filter matches the const. Also: migration 0331 says baselines exist for "the Jackin-used widget subset" without a count; the actual counts are 17 components / ≥87 stories asserted / 107 PNGs committed.
- **Version stamping is internally inconsistent at HEAD**: workspace `version = "0.11.0"` (root `Cargo.toml:13`) and intra-workspace dep pins say 0.11.0, while `migrations/0317…0331` all target `v0.14.0` and `RELEASING.md` requires the version bump to land atomically with the first breaking change of a boundary. Git tags stop at `v0.9.0`. Consequence for consumers: pin by git rev; `version = "=0.11.0"` in a git dep will keep matching even as migration numbering says v0.14.0.
- **The "plan ledger" (assumption A3) is referenced by shipped test text and research but is not committed** — searched `research/`, `roadmap/` (README only), `artifacts/` (empty). Dead end in-repo.
- **`termrock-raster` is not at the repo root** despite top-level `termrock-raster/` appearing in some listings — the real crate is `crates/termrock-raster`; the root-level names in `ls` output were an artifact of RTK output formatting listing `crates/` children inline.
- **Who blessed the 107 baselines is not recorded** (no platform metadata in the commit). Indirect evidence both ways exists: this macOS host reproduces all 107 exactly (measured), and TermRock's PR lane that runs the same test is Linux-only per its research doc, with `e1d61f4d` merged to main — consistent with macOS↔Linux identity holding for this set, but not proof (CI green status not verifiable from the local clone). MED.

## Open unknowns

Best available: cross-arch identity measured on one OS (HIGH), this-host macOS reproduction of committed baselines (HIGH, measured here), Linux CI presumed green on the merge (MED, inferred). The shipped fallback if it ever breaks: pinned-Linux or CI-produced bless (`png_baselines.rs:69`).
- **Runner OS mix for jackin CI render tests**: injected from external SHA-pinned velnor-actions (`rust-nextest.yml` `runner-configs-json` input); not determinable from the jackin tree alone.
- **`.snap` enumeration implementation** (TESTING.md:181 policy) lives in external velnor-actions; unread.
- **Cargo `publish = false` vs git-dep consumption**: behavior asserted from the Cargo Book URL (not re-fetched); a one-line test build of `termrock-raster` as a git dep from outside the workspace would close it.
- **Color-table lockstep**: `termrock-raster/src/color.rs` is deliberately duplicated from lookbook code "until unified" (`color.rs:6-7,45-46`) — whether a consumer-visible unification is planned is not stated anywhere read.
